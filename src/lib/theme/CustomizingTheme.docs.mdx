# Customizing Theme & Styling (`theme` Prop, Tailwind & CSS)

`@vicacha-devs/astro-tiptap-blocks` ships with a layered styling architecture so you can adapt every block using **Tailwind CSS**, **custom utility/BEM classes**, or **pure CSS `data-*` selectors**.

---

## 1. How the Theme Engine Works (`TiptapBlockUserTheme`)

Every `<TiptapBlocks />` instance resolves its classes through `buildThemeObject(userTheme, TiptapBlockThemeDefault)` (`src/lib/theme/theme.ts`) in three layers:

1. **Base Layer (`TiptapBlockThemeDefault`)**: Default Tailwind utility classes for all 21 block types and their sub-elements.
2. **Overwrite Layer (`theme.overwrite`)**: **Replaces** only the specific slots you provide while keeping all other default slots intact.
3. **Extend Layer (`theme.extend`)**: **Appends** your custom classes onto the resolved slot value.

Every slot accepts either a space-separated `string` or a `string[]` array.

### Example: Extending Default Tailwind Classes (`theme.extend`)

```astro
---
import { TiptapBlocks } from "@vicacha-devs/astro-tiptap-blocks";
---

<TiptapBlocks
  data={article.content}
  theme={{
    extend: {
      default: "max-w-prose mx-auto",
      heading: {
        default: "font-serif text-emerald-950 dark:text-emerald-100",
        h2: "border-b border-emerald-500/20 pb-2",
      },
      paragraph: {
        default: "text-slate-700 dark:text-slate-300",
        link: ["text-emerald-700", "dark:text-emerald-400", "font-medium"],
      },
      informationPane: {
        tip: "shadow-sm ring-1 ring-purple-500/20",
      },
      table: {
        headerCell: "bg-slate-100 dark:bg-slate-800/70",
      },
    },
  }}
/>
```

### Example: Replacing Classes with BEM / Vanilla CSS (`theme.overwrite`)

If your project does not use Tailwind CSS (or uses custom design-system classes for specific blocks), use `overwrite`:

```astro
<TiptapBlocks
  data={article.content}
  theme={{
    overwrite: {
      default: "richtext-body",
      informationPane: {
        default: "callout",
        info: "callout--info",
        success: "callout--success",
        warning: "callout--warning",
        danger: "callout--danger",
        neutral: "callout--neutral",
        tip: "callout--tip",
        title: "callout__title",
        body: "callout__body",
      },
      code: {
        default: "code-block",
        line: "code-block__line",
      },
    },
  }}
/>
```

> You can also combine `overwrite` and `extend` in the same `theme` object—`overwrite` runs first, and `extend` appends on top of it.

## 3. Styling via Semantic `data-*` Attributes & CSS Variables

Every component also emits semantic `data-*` attributes so you can style blocks in global/scoped CSS without modifying the `theme` prop:

```css
/* Target callout variants directly in CSS */
[data-type="information-pane"][data-variant="tip"] {
  border-inline-start-color: #8b5cf6;
}

/* Switch Shiki code tokens from dark palette to light palette when desired */
pre[data-shiki="true"].light-code-block .shiki-token {
  color: var(--shiki-light) !important;
}

/* Style line numbers emitted by showCodeLineNumbers */
pre code [data-line-number]::before {
  content: attr(data-line-number);
  display: inline-block;
  width: 2rem;
  margin-inline-end: 0.75rem;
  text-align: end;
  opacity: 0.45;
  user-select: none;
}
```

## 4. Programmatic Theme Helpers (`@vicacha-devs/astro-tiptap-blocks/lib`)

When building custom block components (`blocks` prop), use the exported theme utilities so your custom components honor the user's `theme`:

```ts
import {
  TiptapBlockThemeDefault,
  buildThemeObject,
  getPropertyClass,
  renderPropertyClasses,
} from "@vicacha-devs/astro-tiptap-blocks/lib";

// Combine `default` + variant slot (e.g., `informationPane.default` + `informationPane.warning`)
const calloutClass = renderPropertyClasses(theme.informationPane, "warning");

// Read a single sub-slot (string or string[]) as a normalized class string
const titleClass = getPropertyClass(theme.informationPane.title);
```
